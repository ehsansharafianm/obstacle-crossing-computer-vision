# 2026-08-28 — 3× Pixel-8 ultrawide rig, robust sync, clearance-ready

Migrated the whole system from **2 iPads** to **3 Google Pixel 8 phones**, and hardened
the pipeline into a clean, self-checking 3-camera tool. See [[progress-log]] for the
running story and [[next-steps]] for what's left.

## Headline
- **3-camera pipeline working end-to-end on the Pixel rig** — calibrate → clap-sync
  (all 3) → track → n-view 3D → world frame → xlsx/plots + aligned review videos.
- **test10 (ultrawide, normal 60 fps): L foot 16 mm, R foot 12 mm** toe-heel std,
  full lift/landing arcs, all three cameras contributing.

## What we did
### Rig migration (Pixel 8 × 3)
- Per-phone **intrinsics** for cam1/cam2/cam3, validated with the split-half fx test.
- Learned the recording constraints (saved to memory [[pixel-slowmo-calibration-setup]]):
  **video stabilization MUST be off** (EIS shifts the principal point ~110 px), HEVC is
  fine, and ¼ slow-mo stores 120 fps as ~30 fps (÷4 timing) — later dropped for ultrawide.
- **Auto-detect recording mode**: normal ~60 fps vs ¼ slow-mo, from the clip fps.

### Calibration (one command, now 3-camera)
- `build_calibration N` computes cam1↔cam2 + floor **and** cam2↔cam3 (cam2 is the hub).
- Fixed a **runaway hold-matcher**: the O(N²·N) consistent-set search exploded on long
  (4-6 min) calib clips → capped board holds at 40.
- calib10 (ultrawide, cameras raised to ~1.28 m): cam1↔cam2 **0.71 px**, floor **0.52 mm**,
  cam2↔cam3 **0.97 px**.

### The clap-sync saga (the big win)
- The clap **works**, but the detector was wrong for the new modes. Fixes:
  - Slow-mo stretches the clap into a broad **hump** → detect the hump, not a spike;
    widened the search **window** (hand-started cameras differ by many seconds).
  - Normal 60 fps gives a sharp but sometimes **quiet** clap (prominence ×3-4).
- Root fix — **rigid-shoe-arbitrated, clap-SEEDED sync**: pick each camera's offset by
  minimising toe-heel scatter (rigid shoe = constant length), **seeded** by the clap +
  motion candidates. This survives a quiet clap and a false motion-sync peak, and (on
  test10) found cam3's true **+13.7 s** offset that sat outside the ±9 s coarse window.
- cam3 is synced against cam2 through the **clean cam2↔cam3 pose**, not chained through
  the weaker cam1↔cam2.

### Reconstruction (n-view, 3 cameras)
- Every marker uses whichever cameras saw it (≥2 → 3D). **cam1+cam2 is the precision
  core** — it has the **widest baseline** (~1.98 m vs cam2↔cam3 ~1.11 m), and precision
  scales with baseline, so it reconstructs tighter *despite* cam2↔cam3's lower RMS.
  Forcing cam2+cam3 as core made both feet ~4× worse — a decisive lesson. cam3 fills gaps.

### Ultrawide switch (space-constrained)
- Went to **normal 60 fps + ~0.6-0.7× (ultrawide)** to widen the FOV and catch the full
  lift/landing (couldn't move cameras back — no space). Intrinsics re-shot per phone at the
  new zoom; the **standard distortion model fits** (no fisheye needed), fx ~890-903 (~94°).

### Quality-of-life
- **Time referenced to the clap**: `time_s = 0` is the sync moment; pre-clap frames trimmed.
- **`sync_cut.py`**: auto-writes clap-aligned review clips to `sessions/<id>/synced_videos/`
  (analysis always uses the originals). Runs as the final step of processing.
- **`flip_world_xy.py`** + a build_calibration **axis readout**: report which way +X/+Y point
  and flip both (180° about Z) in one line if the convention is reversed. Applied to calib10.
- Audio-sync figure + xlsx `audio` sheet + MATLAB now cover **all three cameras**.

## Bottlenecks / open issues
- **Coverage vs clutter.** ~60 % of frames a marker is seen by only ONE camera (cam1 ~59 %
  vs cam2/cam3 ~29 %). Keeping single (unpaired) markers doubles detection but locks onto
  **same-coloured background clutter** (a static purple object) that static-clutter masking
  couldn't fully remove → precision 16→33 mm. Reverted to the paired tracker. **Real fix:
  marker colours ABSENT from the lab background** (purple/teal have look-alikes here).
  Note: the clearance moment (foot over obstacle) is already well covered; gaps are mostly
  approach/departure.
- **cam2↔cam3 baseline is narrow** (~1.11 m) → it's a coverage helper, not the precision pair.
- **One residual outlier spike** on the R foot (single bad point; a velocity filter would kill it).
