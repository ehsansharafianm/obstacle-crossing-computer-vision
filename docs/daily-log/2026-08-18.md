## What we did

**1. Reorganized experiments into one self-contained folder per test.**
- New layout `code/experiments/testNN/`: the two input clips (`cam1`/`cam2`) and
  every output live together, with the test id as the prefix on each output.
- One-command workflow: `build_foot_trajectory.py testNN` →
  `testNN_trajectory.csv` + `.png` + `_run.txt` (a per-test record of the numbers).
- MATLAB: `plot_trajectory('testNN')` resolves the path automatically.
- Added `.gitignore` (videos stay out of git; small CSV/PNG/run.txt are kept).
- Confirmed the CSV is **one file per test**, continuous time column, position
  cells blank when the foot is absent — already the behavior the researcher wanted.

**2. Fixed a silent blob-size bug (`detect_foot` max_area 1500 → 20000).**
- Close-up frames make the marker blob large; the old 1500 px cap discarded
  exactly those (best-accuracy) frames. Confirmed: 2708/2405 px blobs were being
  dropped. After the fix, raw detection ~doubled (test02: cam1 24→46%, cam2 38→56%).

**3. BREAKTHROUGH — audio-clap camera sync (`occ/audiosync.py`).**
- The rigid-foot sync was unreliable: on the same footage it guessed −8.75, then
  −17.19, then +11.4 s. A physical offset can't change — the method was wrong.
- The clap the researcher recorded is **not visible in frame** (cameras aimed at
  the floor), but it's a clean, isolated spike in **both audio tracks**.
- Cross-correlating the audio envelopes (opening-window only) + a loudest-peak
  cross-check → **cam2 + (−4.008 s) = cam1, confidence 44**; two methods agree to
  the millisecond. This is now the default sync; rigid-foot is a fallback.
- Needs `imageio-ffmpeg` (bundles a static ffmpeg; no system install).

**4. Removed interpolation that fabricated data across gaps.**
- `interp` was drawing straight lines across multi-second foot-out-of-frame gaps
  (the sawtooth ramps in the plot), inflating coverage and polluting the
  toe–heel metric. Capped to 50 ms; longer gaps stay honestly empty.

**5. Design discussions (decisions logged in [[open-items]] / [[next-steps]]).**
- **fps:** keep 240 for now; drop to **1080/120** later (½ the processing, no real
  loss for trajectory). Keep 1080p resolution. Record low-fps rather than
  downsample. Watch the motion-blur trap at 60 "normal".
- **3 Pixel 8s:** yes to a 3rd camera for occlusion — but *after* one clean 2-cam
  crossing. Matched devices matter more than the brand.

## Challenges hit
- **Sync was the wall.** Rigid-foot offsets were wildly inconsistent on sparse,
  noisy data. Audio clap solved it decisively.
- **Clap invisible to the cameras** (aimed low) → visual sync impossible → audio.
- **max_area** silently dropped the close-up frames.
- **interp fabricated data** across long gaps → false 92% coverage.
- **Marker quality (test03):** flat stickers face away when the toe tilts (green
  reads 0 even with the foot in view); **red was on the ankle, not the heel**, so
  toe–heel isn't a fair rigid-distance check.

## Results — test03 (first clip with a clap)
- **Sync: SOLVED.** Audio clap, cam2 + (−4.008 s), confidence 44. Robust & repeatable.
- Raw detection: ~56–57% per camera.
- Toe coverage: 47% → **60% honest** (the pre-fix 92% was inflated by
  interpolation fabricating data across gaps; 60% ≈ raw 57% + short-gap fill).
- Toe–heel distance: mean ~345 mm, **std ~78 mm — still noisy.** The gap-cap
  removed the fabricated ramps but the std barely moved (67→78), which *confirms*
  the noise is **real per-frame mis-triangulation**, not an interpolation artifact.
  Causes: flat markers facing away (poor 2D centroid) + red-on-ankle placement.
  → The pipeline is sound; the remaining fix is **recording-side (marker quality)**.
